# youth_ministry — AI Agent Guide

Мини-игра-опрос для мероприятия. Участники отвечают с телефонов, оператор
показывает статистику на проекторе.

## Главное про проект

- **Сборки нет.** Чистый HTML + ES-модули + CSS. Никакого npm, bundler, CI.
- **Бэкенда нет.** Firebase Firestore напрямую из браузера (ESM с CDN).
- **Хостинг** — GitHub Pages, публичный репозиторий.
- Всё должно оставаться в пределах бесплатного тарифа Firebase Spark.
  Cloud Functions и Firebase Storage использовать нельзя — они требуют Blaze.

## Структура

```
index.html        экран участника (телефон)
host.html         экран оператора + проектор
app/
  questions.js    контент: вопросы, варианты, картинки
  store.js        доступ к данным, переключатель MOCK ↔ Firebase
  firebase.js     конфиг и реальная реализация Firestore
  participant.js  логика экрана участника
  host.js         логика экрана оператора
  styles.css      все стили
images/           картинки вариантов (пока внешние ссылки в questions.js)
docs/spec.md      ТЗ и принятые решения — читать перед изменениями
```

## Запуск локально

ES-модули не работают по `file://`, нужен локальный сервер:

```bash
npx serve .
# или
python -m http.server 8000
```

Потом `http://localhost:8000/` — участник, `http://localhost:8000/host.html` — оператор.

## Режим моковых данных

`app/store.js`, первая строка: `const MOCK = true`.

При `true` ответы лежат в `localStorage`, «другие участники» генерируются
случайно — чтобы слайдер результатов было чем наполнить. При `false`
работает Firestore. Больше нигде в коде переключение не отражается.

## Модель данных Firestore

```
sessions/{sessionId}  →  { q1: 'mountains', q2: 'coffee', ..., updatedAt }
```

Один документ на участника, перезапись при смене ответа. `sessionId`
генерируется клиентом и лежит в `localStorage`.

Правила: create и update разрешены всем, read разрешён всем (нужен
оператору), delete запрещён всем.

## Соглашения

- Комментарии в коде — на английском.
- Все тексты интерфейса и вопросов — на украинском, прямо в разметке
  (i18n не нужен). Комментарии и документация проекта — как раньше.
- Ответ хранится как **id варианта** (`'mountains'`), не как подпись.
  Подписи меняются, id — нет.
- Правки контента (вопросы, варианты, картинки) делаются ТОЛЬКО в
  `app/questions.js`. Логика не должна знать о конкретных вопросах.
